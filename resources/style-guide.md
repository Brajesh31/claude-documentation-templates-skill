# Documentation Style Guide

## Audience and purpose
State who the document serves and what the reader should be able to do after reading it.

## Structure
- Use one clear H1 title.
- Organize content with sequential H2 and H3 headings.
- Put prerequisites before procedures.
- Put expected results and troubleshooting near relevant steps.
- Use tables for compact comparisons, not long narrative.

## Examples
- Use realistic but fictional values.
- Mark placeholders clearly.
- Include expected output when it helps verification.
- Keep commands copyable and specify the working directory.
- Never include real secrets, personal data, or production credentials.

## Maintenance
Include version context when behavior changes across releases. Link to canonical references. Add an owner or review cadence for operationally important documents.

## Code comments
Comment on intent, invariants, trade-offs, and non-obvious behavior. Avoid comments that merely repeat the code. Update comments when behavior changes.
